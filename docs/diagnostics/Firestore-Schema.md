# Purpose

This document defines the Firestore data model for the Diagnostics Platform.

It specifies:

- Collections
- Document structure
- Field ownership
- Required fields
- Optional fields
- Indexes
- Security expectations

---

# Collection

```text
debug_reports
```

Each diagnostics report is stored as one document.

---

# Document ID

Firestore document IDs are generated by the backend.

The client must never choose the Firestore document ID.

---

# Document Structure

```text
debug_reports
    └── {reportId}
```

# Firestore Indexes

Version 1 should include indexes for:

```text
status + receivedAt DESC

duplicate + receivedAt DESC

clientReport.app.platform + receivedAt DESC

clientReport.app.appVersion + receivedAt DESC

clientReport.reason + receivedAt DESC

clientReport.severity + receivedAt DESC
```

---

# Security Rules

Clients:

```text
No read

No write

No update

No delete
```

Cloud Functions:

```text
Create

Read

Update
```

Admin:

```text
Read

Update
```

Only administrators may update:

- status
- reviewedAt
- reviewedBy
- adminNotes
- duplicate
- duplicateOf

---

# Future Fields

Reserved for future versions:

```text
attachments

networkInfo

performanceMetrics

memoryUsage

battery

aiClassification

githubIssue

slackThread

releaseChannel
```

These fields must not be implemented in Version 1.

---

# Final Rule

The backend owns the Firestore document.

Flutter owns only the `clientReport` payload.

No Flutter code may write directly to the `debug_reports` collection.
