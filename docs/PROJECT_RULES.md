# 🐾 Petsupo Project Rules

Version: 1.0

---

# Mission

Build the best pet ecosystem with clean architecture,
predictable UX, and maintainable code.

---

# Development Principles

Documentation First

Architecture First

Prototype First

Backend Second

Production Last

---

# Code Principles

Small commits

Single responsibility

No large refactors

Feature-based structure

State machine preferred

Composition over inheritance

---

# Product Principles

User experience is more important than implementation speed.

Never add complexity without product value.

Every screen should have one primary action.

---

# Documentation Rules

Every major feature must have:

PRD

Architecture

Wireframe

State Machine

Firestore Schema

Sprint Plan

ADR

before implementation starts.

---

# AI Collaboration Rules

Before generating code:

Read PROJECT_RULES.md

Read feature README.md

Read Architecture

Read ADR files

Then implement.

Never bypass documented architecture.

---

# Commit Rules

One feature

One purpose

One commit

---

# Review Checklist

Compiles

No warnings

No dead code

No duplicated logic

No breaking changes

Documentation updated

---

# Definition of Done

Code works

Architecture respected

Documentation updated

UI matches wireframe

Ready for production

---

# Philosophy

Slow planning.

Fast implementation.

Stable production.
